The screen sharing checklist

How to hide sensitive data before screen sharing

By SD Software, makers of Nixel · 20 October 2026

The dashboard is ready. The call is starting. An email address in the sidebar and an API key in the settings are easy to overlook. A few minutes of preparation make the shared view much easier to check.

Start with the smallest thing you need to show

If a single browser tab is enough for the demo, share that tab. A full desktop share can also show notifications, other windows and files that have nothing to do with the call.

Use a demo account with fictional data when you can. Close unrelated tabs, dismiss notifications and visit each page you plan to open. If the demo needs a real account, look for details that belong to customers, colleagues or your own infrastructure.

Check more than the big numbers

  • Credentials: API keys, access tokens and connection details in settings, tables or code examples.
  • Contact details: names, emails and phone numbers in account menus, activity feeds and support conversations.
  • Billing details: card numbers, addresses and information shown on invoices.
  • Internal details: private IP addresses, hostnames and anything your audience doesn't need to see.

This is also a useful time to close a page entirely if it contains information that doesn't belong in the demo.

Cover sensitive text in Chrome with Nixel

We built Nixel for this part of the workflow. It detects supported sensitive text on Chrome pages and places masks over it. Here's how to use it before a call or recording:

  1. Install and pin the extension. Get Nixel from the Chrome Web Store, then open the page you plan to show.
  2. Review the detections. Open Nixel from Chrome's toolbar. Check which categories it found and switch off categories that would hide information you need to discuss.
  3. Enable name detection if you need it. Names, addresses and organisations use an optional local language model. Allow time for the first download, about 100 MB, before the meeting.
  4. Choose a mask style. Blur, pixels, solid bars and labels change how covered text looks. For sensitive text in a recording or screenshot, use opaque bars or labels and inspect the result closely.
  5. Check the shared view. Start a private test recording or use the preview in your sharing tool. Open menus and move through the pages you'll show. Make sure the masks and the rest of the page appear as expected.

Watch the 35-second demo to see the actual extension, mask controls and screenshot editor.

Keep a final review in the process. Automatic detection can miss things. Nixel works with supported page text and doesn't cover other apps or your entire desktop. Don't rely on it to detect sensitive text inside images, videos or browser controls.

If you're sending a screenshot

Use Nixel's screenshot capture to open the page in its editor with detected items covered. Review the masks, turn individual findings on or off as needed and choose a mask style before copying or saving the PNG.

Open the exported image once more before attaching it. Check the corners, headers, sidebars and any text the detector didn't identify. If something sensitive is still visible, fix the image or leave it out.

What stays local

Nixel processes page content inside your browser. It doesn't send that content to us or to an AI service. The optional language model is downloaded once and then runs locally. Paid licence checks go to Lemon Squeezy without page content. The privacy policy explains those requests.

Before you press Share

  • The selected tab or window is the one you meant to show.
  • Unrelated tabs, windows and notifications are out of view.
  • Credentials and personal details are covered or removed.
  • You checked the pages and menus you plan to open.
  • A test recording or preview shows the result you expected.
